## 一、系统定位与核心思想

本系统是"基于计算机视觉和轻量VLM的干涉法测量热膨胀智能实验系统"：用迈克尔逊干涉法 + He-Ne 激光（632.8nm）全自动测量黄铜 H62 的线膨胀系数 α。

核心设计决策：**AI 感知 + 物理计算**——卷积网络负责"看"（定位环心、选采样半径、判帧质量），经典物理算法负责"算"（条纹相位解调与计数），两者构成共生测量管线。不把 AI 当万能黑箱，只部署在它真正擅长的感知位置。

实验中的"看、算、控、判"四个能力维度分别由三类 AI 承担：

| AI 组件 | 角色 | 替代了实验者的什么 |
|---------|------|--------------------|
| 三头 CNN（FrameAnalysisNet） | 感知层 | 眼睛：看条纹、找环心、判质量 |
| Qwen3-VL 4B Agent（9 阶段指导 + 反应层 + 19 工具） | 决策层 | 手+脑：引导实验流程、调仪器、控温度、安全联锁 |
| RAG 知识增强 + 🌐 联网搜索 | 知识层 | 脑：讲解原理、故障诊断、组织流程 |

## 三、测量链路（一帧数据的旅程）

1. 相机以 20fps 采帧 → 红通道提取（He-Ne 波长对应）
2. FrameAnalysisNet 三头 CNN 单次前向（<2ms）：输出光心 (cx,cy)、3 个采样半径 r0、质量分 q
3. PhaseFringeCounter 空间相位计数：s=r² 椭圆极坐标展开 → FFT 窄带解析信号 → K 通道解缠绕 → Theil-Sen 拟合外推 φ₀ → 带符号 N(t)
4. Q 驱动惯性滑行：质量 q<0.5 的坏帧以干净帧均值惯性推进，不污染计数
5. NRateGate 输出限速 ≤2 条/s，跳变帧惯性覆盖
6. α = N·λ/(2·L₀·ΔT)；temp 模式使用配置段温差，fringe/free 模式使用段内实测 PV 温差
7. 温控经 Modbus 每 0.5s 同步 PV/SV/MV 到系统状态

无硬件时可用**视频模拟源**：回放实验视频走完全相同的分析链路，加载后自动进入测量计数。

## 四、AI 模块细节

### 4.1 FrameAnalysisNet（三头 CNN）

约 630K 参数，输入 256×256 灰度帧，单次前向同时输出：
- 光心头 v2：16×16 空间热图 + softmax 期望做亚格点定位（中位误差 26px vs 人工真值；v1 的 GAP+FC 回归因空间维被平均化，定位天花板仅 ~136px）
- R0 头：3 个采样半径（分散铺设，外推基线更长更稳）
- 质量头：MobileNetV3 倒残差风格，AUC=1.0（退化负样本重训）；q<0.5 触发 coast 滑行

光心策略：热身 64 帧锁定初始中心 + EMA 温和跟随（系数 0.02），不逐帧硬跟（实测逐帧硬跟导致漏计）。前端顶栏可切换 **cnn / cv** 两档光心判定模式（auto 自动仲裁已移除）。

### 4.2 PhaseFringeCounter（带符号空间相位计数）

基于傅里叶变换法（FTM, Takeda 1982）从空间条纹直接解调相位，方向自动区分：涌出 +1、缩入 −1，加热首尾往复自动抵消。三层架构：增量层（每帧 ~8ms 实时）、权威层（每 200 帧全段重拟合校正漂移）、定标层（掩膜热替换）。关键参数：K=9 通道、带通 (0.4,1.7)f₀、360 角向×400 径向采样。

### 4.3 Agent 实际架构：9 阶段指导 + 反应层 + 对话工具层

当前 Agent 以**分步实验指导为核心**：

- **9 阶段实验指导（ExperimentGuide）**：开题安全→样品安装→光路粗调→光路细调(VLM验证)→相机成像(Q≥0.75)→初始温度→自动扫描→数据处理→报告关机。每阶段含目标/操作/通过标准/agent 讲解（RAG+实时状态+vision 附当前帧）；软门控——本阶段未达标时 next() 返回 warn(提醒不阻止)，可 force 跳过；验证分 state(实时状态)/vision(VLM 关键词判定)/none(手动确认) 三类
- **反应层（SafetyGuard）**：纯规则检查，主进程每 2s 运行。温度超过 60℃ 时关闭加热并停止扫描；Q<0.4 持续 3s → 提醒（60s 冷却，仅指导阶段≥4 或测量/扫描中启用）；质量突降时提示条纹可能丢失。告警文案注入双端聊天并由 /ws/measure 推送
- **对话工具层**：19 个工具 function calling（start_guide 置顶），RAG + 联网搜索 + 文件上传 + 附带相机帧，SSE 流式（think/tok/tool/done）

Agent 对话能力：多轮记忆（20 轮）、硬件工具调用（带前置检查与输入钳制，set_temperature 受 60℃ 安全上限约束）、RAG 知识问答增强、附带当前相机画面、深度思考开关。

### 4.4 RAG 知识增强

bge-m3 嵌入（1024 维）+ numpy 余弦检索（<1ms）。知识源为 docs/ 下整合文档（光路指导、物理原理、项目知识、CV/CNN 理论，共 64 片）。**动词门控** `route_query`：操作诉求触发工具、知识诉求触发 RAG，可同时成立。另有 🌐 联网搜索（cn.bing.com）作为第二知识源。

### 4.5 结果报告

段结算后报告：
- α 均值 ± 段间标准差（`scan_runner.result()` 的 alpha_avg/alpha_std）
- 与参考值 20.8 的相对误差 error_pct
- 各段明细 {seg, T1, T2, ΔT, N, α} 写入 CSV + 前端段表

已知边界：PT100 读数与样品真实平均温度之间可能存在热滞后，该系统差尚未单独定量标定。

## 六、温度扫描三模式

| 模式 | 行为 | 适用 |
|------|------|------|
| temp（温度步进，默认） | 30→50℃ 每 5℃ 一段：进段 3s 确认→开计数→升下一段→段末结算 α | 标准实验 |
| fringe（N 步进） | 连续升温，每累计 n_step 条结算一段（N 固定、dT 实测） | 快速粗测 |
| free（即时计数） | 不控温，启动即计，停止时结算 | 手动加热配合 |

关键约定：相机未取流且未加载视频时禁止启动测量/扫描；temp 模式按配置温度段计算 ΔT，fringe/free 模式按实测 PV 计算；dT<0.05℃ 的段 α 标无效；扫描结束 temp/fringe 模式自动关加热；free 模式不碰温控。

## 八、使用与故障速查

启动：conda 环境 ocv → `uvicorn app.main:app --host 0.0.0.0 --port 8080`，浏览器开 http://localhost:8080（移动端 /mobile/）。前提：Ollama 运行中（ollama list 应有 qwen3-vl:4b 与 bge-m3）。

| 现象 | 处理 |
|------|------|
| 测量/扫描被拒 | 先启动相机取流，或加载视频模拟源 |
| 光心不准 | 顶栏切换 cnn/cv 判定模式对比 |
| 指导下一步被提醒"未达标" | 软门控设计：完成本阶段或点"下一步"强制跳过 |
| 反应层告警不出现 | Q 告警仅指导阶段≥4 或测量/扫描中开启，实验一开始不提示 |
| N=0 | 等待 64 帧热身定标，检查信号强度、曝光，并确认测量已启动 |
| α 偏差大 | 核对扫描模式采用的 ΔT 口径和段起止温度 |
| Agent 不可用 | 确认 Ollama 运行 |
| 温控离线 | 设备管理器确认 COM 号，顶栏重连 |

独立工具：autotune_pid.py（PID 自整定）。
